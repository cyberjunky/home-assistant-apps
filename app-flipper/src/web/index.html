The Flipper has one serial port, and it either talks to this app (screen, buttons, files) or is a command line. While the console is open the screen and files wait; closing it brings them back.

  


  
  

    

      
What this is

      
A workbench for a Flipper Zero plugged into the machine Home Assistant runs on. It shows the Flipper's screen, presses its buttons, reads and writes its files, and builds and starts apps on it. Not made by or affiliated with Flipper Devices.

      
C apps

      
A project with an application.fam is a C app. Build runs ufbt, Flipper's own build tool, which makes a .fap. Build & run then puts it in /ext/apps/<fap_category>/ on the SD card and starts it. An app that is running is closed first.

      
ufbt needs the Flipper SDK and compiler: about 400 MB to download, 1.5 GB on disk, kept in the app's data and left out of Home Assistant's backups. Install it on the Code page. An app only loads on firmware with the same API as the SDK it was built with, so take the SDK that matches your Flipper's firmware (release for a Flipper on release firmware).

      
JavaScript

      
A project without an application.fam is a set of scripts. Run puts them in /ext/apps/Scripts/<project>/ and starts the open one with the Flipper's JS Runner. No SDK is needed. What a script prints shows on the Flipper's screen.

      
The log

      
FURI_LOG_I() lines go to the Flipper's log, which the Console shows (Show log). The log and the screen cannot be shown at the same time: see the note on the Console page.

      
When the Flipper needs its USB port

      
While this app holds a session, the Flipper cannot switch its USB port to another role (Bad USB, U2F, the USB-UART bridge). Release on the Device page ends the session until you connect again.
